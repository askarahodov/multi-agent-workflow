## 4. Важные блокеры и риски

1. **P0 — `ESTOP` локального dispatch.** На момент опубликованного snapshot автоматические запуски остановлены. Координатор должен зафиксировать актуальное фактическое состояние и причины удержания блокировки.
2. **P0 — `t_26938b85`:** `workspace_kind=dir`, `workspace_path=None`; координатор отмечает задачу `blocked`. Не возвращать в очередь без корректного workspace.
3. **P1 — 11 заблокированных задач.** У ряда задач `blocked` без записанной причины; для некоторых исчерпан бюджет итераций. Нужен разбор зависимости/причины, а не массовый автоматический retry.
4. **P1 — 429/free-tier quota.** Переход на платную модель позволил восстановить доступность провайдера по словам владельца, но корневое исправление парковки `quota_exhausted` в локальном диспетчере не подтверждено.
5. **P1 — полноценная архитектурная и E2E-приёмка.** Обновлённые статусы локального Kanban не заменяют проверку публикуемых diff/ADR и полного нативного Agent Loop.
6. **P1 — CI в служебной ветке.** Последний проверенный запуск `coord/external-qa` красный; не смешивать с ранее зелёными проверками PR #15 или текущим статусом `main`.

### Правило актуализации

**Владелец автоматического обновления панели — локальный `@orchestrator`.** В каждом успешном цикле синхронизации он должен формировать эту страницу **из текущего локального Kanban, опубликованного snapshot и проверенных GitHub-результатов**, а не редактировать устаревшие числа вручную. Обновлять статус проверки только при наличии доказательств. Публиковать `QA_DASHBOARD.md` в одном commit с `status/current.md` и изменённым `requests.md`, никогда не изменяя `responses.md`.

Пока у координатора не установлен автоматический рендер, этот документ остаётся **ручным первичным snapshot от 13.10.2026**. Не считать его живой панелью до доказанного обновления cron.
