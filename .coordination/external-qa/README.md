# External QA handoff — локальная команда ↔ ChatGPT

**Связь:** `coord/external-qa` — выделенная служебная Git-ветка только для обмена результатами, **без merge в main**.
**Единственный источник истины о задачах:** локальная Kanban-БД команды, НЕ этот каталог и НЕ GitHub Issues.
**Внешняя задача:** `EXT-REVIEW-001 / t_2eaa57b1`, режим **read-only / manual hand-off**.

## Панель для владельца проекта

**[Открыть QA_DASHBOARD.md](QA_DASHBOARD.md)** — сводка на русском языке: статус команды, задачи, блокеры, подтверждённые результаты CI/QA и следующий checkpoint.

Детальные источники: [локальный snapshot](status/current.md), [запросы координатора](requests.md), [ответы ChatGPT](responses.md), [регламент автосинхронизации](AUTOMATION_PROTOCOL.md).

Панель первоначально создана внешним QA как снимок. **Дальнейшее обновление `QA_DASHBOARD.md` — ответственность локального координатора**, вместе с `status/current.md` через его cron (каждые 15 минут). Чат-автоматизация внешнего QA настроена на почасовую проверку; это отдельный процесс, который не обновляет локальный Kanban.

## Роли и права записи

| Участник | Читает | Изменяет |
|---|---|---|
| Локальный координатор | `requests.md`, `responses.md` | **только** `requests.md` |
| Внешний QA ChatGPT | `requests.md`, `responses.md`, доступный репозиторий | **только** `responses.md` |
| Исполнители локального Kanban | по усмотрению координатора | не изменяют файлы обмена напрямую |

Служебная ветка не содержит продуктовых изменений, архитектурных решений или исправлений CI. Не редактировать активные worktree `wt/t_005a92be`, `wt/t_759fb8e6`; не делать force-push.

## Протокол

1. Координатор добавляет в конец `requests.md` новый запрос `QA-REQ-YYYYMMDD-NNN` и публикует commit в ветку `coord/external-qa`.
2. Чтобы запрос мог быть выполнен, его доказательства должны быть доступны ChatGPT: текст в запросе, **запушенная** ветка/commit GitHub, либо отдельные переданные пользователем файлы. Локальные незапушенные worktree, `/tmp`, `~/.hermes`, `gateway.log` недоступны внешнему QA.
3. Внешний QA выполняет почасовую проверку через отдельную включённую автоматизацию ChatGPT; также пользователь может вручную инициировать её словами «проверь обмен QA». Локальный cron и автоматизация ChatGPT независимы; наличие файлов в GitHub само по себе не запускает новый сеанс ChatGPT.
4. ChatGPT читает `requests.md` и соответствующие доступные материалы и добавляет ответ `QA-RSP-YYYYMMDD-NNN` в `responses.md` отдельным commit в ту же ветку.
5. Координатор считывает `responses.md`, записывает результаты/назначения в **локальный Kanban** и, при необходимости, создаёт следующий `QA-REQ`. Ответы в Git сами по себе **не меняют** статусы Kanban.
6. Исправления и ревью закрываются **только** по доказательствам: Git diff/commit, stdout тестов, CI, воспроизводимые логи и верификация QA. Наличие сообщения или `exit 0` от mock-теста не равно полноценной E2E-приёмке.

## Формат запроса (координатор → ChatGPT)

Добавлять в конец `requests.md` без удаления старых записей:

```md
## QA-REQ-20261013-001
- local_task: t_005a92be
- category: architecture-review
- priority: P0
- status: OPEN
- source_commit: <точный SHA GitHub или "local-only">
- evidence: <путь в опубликованной ветке, ссылки на CI, sanitized logs>
- question: <конкретный вопрос и критерии проверки>
- constraints: read-only; no changes to local Kanban or worktrees
```

Для `source_commit: local-only` нужно либо опубликовать артефакты без секретов, либо явно сказать, что проверка пока ограничена опубликованными материалами.

## Формат ответа (ChatGPT → координатор)

Добавлять в конец `responses.md`:

```md
## QA-RSP-20261013-001
- request: QA-REQ-20261013-001
- verdict: PASS | CHANGES_REQUESTED | BLOCKED | INFO
- verified_against: <sha/ветка/артефакты>
- findings: <связанные наблюдения с доказательствами>
- acceptance_required: <проверки для закрытия>
- action_owner: <роль без изменения локального Kanban>
```

## Границы и безопасность

- Не публиковать API-ключи, секреты, auth headers, персональные данные, полные приватные логи или незамаскированные environment dumps.
- Не редактировать одновременно один и тот же файл; при non-fast-forward fetch+rebase и повторный push, без force.
- Не мержить ветку обмена в `main` автоматически.
- Выводы ChatGPT ограничены теми кодом и логами, которые ему действительно доступны.
- Hermes Bridge может обслуживать запросы локального агента, но **не** даёт ChatGPT прямой произвольный доступ к локальной Kanban-БД, файловой системе или gateway.log.
