# Операторский интерфейс аварийного восстановления (Issue #38)

Раздел **«Аварийное восстановление»** доступен из бокового меню
Multi-Agent Platform. Это защищённая административная поверхность для
проверки прерванных попыток — не интерфейс повторного запуска агента.

## Что доступно

1. Список задач, переведённых сервером в карантин после прерванного
   выполнения: `GET /api/v1/admin/recovery-quarantine`.
2. Последнее подтверждение оператора:
   `GET /api/v1/admin/tasks/{task_id}/reconciliation`.
3. Реальные **обезличенные** состояния файловых инструментов,
   `CLAIMED / SUCCEEDED / DENIED`, только из доверенного
   read-only Tool Ledger:
   `GET /api/v1/admin/tasks/{task_id}/tool-ledger`.
4. Ручная фиксация решения:
   `POST /api/v1/admin/tasks/{task_id}/reconciliation`.
   `UNKNOWN` фиксирует неопределённость;
   `CONFIRMED_SIDE_EFFECT` и `CONFIRMED_NO_SIDE_EFFECT` требуют
   проверки доказательства сервером и предварительного просмотра журнала
   в интерфейсе. Для любого решения требуются идентификатор доказательства,
   64-символьный SHA-256 и явное подтверждение оператора.

**Никакой кнопки «повторить», `claim_task`, `retry` или запуска
инструмента здесь нет.** Даже подтверждённый исход оставляет старую
задачу в статусе `blocked`. Для продолжения требуется отдельное
создание новой работы после внешней проверки артефактов.

## Режимы и отказоустойчивость

- Frontend использует **существующий** `ApiAdapter` и настройки
  аутентификации, отдельные браузерные ключи не добавляются.
- При HTTP 401/403 выводится сообщение о необходимости доступа
  администратора; нет обхода прав или автоматической повторной отправки.
- Если Tool Ledger не настроен (503), интерфейс допускает только
  `UNKNOWN`. `NO_RECORDS` не означает, что side effects отсутствуют.
- Все HTTP-запросы запускаются по выбору пользователя или при открытии
  раздела; фонового polling и модельных запросов нет.
- Offline `MockAdapter` не симулирует админские решения и всегда
  отклоняет запись. Для настоящей сверки требуется действующий backend
  и роль admin.
- В режиме Vite запросы `/api/v1/admin` маршрутизируются в
  `ORCH_UPSTREAM`, как другие endpoint orchestration-server.

## Принятие

```bash
cd frontend
npm ci
npm run typecheck
npm run test:run
npm run build
```

Компонентные регрессии проверяют явное подтверждение,
`CLAIMED`-предупреждение, недоступность журнала, неизменяемое
подтверждённое решение, RBAC 403 и отсутствие вызова
`claimTask`/`submitTask`.

**За пределами этапа:** production RBAC/SSO конфигурация, работа с
удалённым Tool Ledger, хранение и версия доказательств, контролируемое
создание новой задачи и полноценный workflow reconciliation (#38).
