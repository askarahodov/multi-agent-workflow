## Порядок изменения

Новые общепроектные ADR размещать в `docs/adr/`. Указывать ID, владельца области, дату, статус, контекст, решение, альтернативы, последствия, риски, ссылки на требования, контракт и проверку. При замене — явно связать старый и новый ADR; не менять статус на Accepted без подтверждённого согласования. В этом реестре обновлять ссылку и статус в том же PR. Не исправлять исторические evidence задним числом. Актуальная граница native runtime описана в ADR-111; ранние предложения о Hermes не использовать как инструкции продукта.
