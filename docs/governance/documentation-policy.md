# Порядок сопровождения документации

Версия 0.1, проект для согласования. #340, #334. Русский язык — основной для продуктовой, пользовательской, операционной и организационной документации, инструкций и отчётов. Технические спецификации, API reference, код, схемы, машинные ключи и исходные логи могут оставаться на английском. Не создавать независимую копию перевода; обновлять канонический материал. Архивные evidence не переписывать.

## Владение и жизненный цикл

Для активного документа определить владельца подсистемы по OWNERSHIP, статус active/draft/historical/superseded, ссылку на канонический материал, дату/версию ревью. При изменении поведения, API, конфигурации, ролей, security boundary или миграций обновить соответствующий документ в том же PR. Устаревший материал не выдавать за инструкцию; сохранять evidence и явно отмечать статус. Технические исключения фиксировать по причине.

## Первичный реестр работ

| Область | Наблюдение | Действие |
|---|---|---|
| VitePress index/nav | Англоязычная навигация и placeholder your-org | Локализовать навигацию, исправить ссылки; данный PR |
| ADR | docs/adr и docs/developer/architecture-decisions содержат одинаковые IDs | Сверить содержимое и ссылки, определить canonical; не удалять до review |
| Версионирование | Старые пути frontend/, shared/, service directories | Сверить manifests и обновить руководство |
| Agent development / quality gates | Исторические команды Hermes/Kanban могут относиться к разработке платформы, а не продукту | Сверить реальные команды, разграничить dev/runtime |
| Пользовательские руководства | Смешанный русский/английский | Инвентаризация и перевод активных страниц после проверки поведения |
| Операционные руководства | Англоязычные guides, часть примеров может устареть | Проверка на фактическом Compose/RKE2; перевод по мере подтверждения |
| История и audit | Датированные evidence и reports | Сохранить оригинал, добавить актуальный указатель |
| Технические контракты | OpenAPI/AsyncAPI/JSON Schema | Не переводить wire keys, использовать ссылки на owner; #337/#346 |

## Проверки

Использовать существующие docs CI: npm ci, VitePress build, node link resolver, generated links и Chromium smoke. Не отключать проверку ссылок. JSON/YAML вне публикуемых assets указывать путём в Git, не ссылкой на несуществующую страницу сайта. Проверки устаревших путей, языковых исключений, владельцев и doc impact развивать отдельно с тестами. Наличие этого документа само по себе не подтверждает перевод всего портала.
