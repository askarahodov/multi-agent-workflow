# Порядок сопровождения документации

Версия 0.2, проект #340 для согласования. Русский — основной язык продукта, инструкций, эксплуатации и организационных материалов. Английский допустим для технических спецификаций, машинных контрактов, кода, CLI, исходных evidence. Не создавать вторую редактируемую копию перевода.

## Реестр и ответственность

[Реестр документов](documentation-inventory.md) объясняет машинный реестр documentation-inventory.json. Каждая Markdown/JSON/YAML запись внутри docs имеет статус, владельца области (по OWNERSHIP, не фиктивный GitHub reviewer), язык/причину исключения и состояние review. UNKNOWN означает отсутствие подтверждения; canonical означает редактируемый источник, не принятую реализацию. Архивные evidence не переписывать. При добавлении, удалении или переносе документа обновлять реестр в том же PR.

ADR редактировать в docs/adr; старые адреса VitePress используют include. [Индекс](../developer/architecture-decisions/adr-index.md) сверяется с источником, а не подменяет его. Исторические ссылки внутри ADR сохраняются как свидетельство исходного контекста; не интерпретировать их как актуальные команды.

## Doc impact

При изменении API, конфигурации, поведения, ролей, security boundary или миграции обновить соответствующий канонический документ в том же PR. При отсутствии влияния заполнить отдельную строку `Doc impact: none — <причина>` в PR. Автоматический guard проверяет наличие изменения docs или явного обоснования для затронутых областей, но не качество обоснования — это обязанность reviewer. Не выдавать техническое исключение за освобождение от актуальности документации.

## Проверки

Существующий docs CI сохраняет npm ci, VitePress build, link resolver, generated links, audit и Chromium smoke. Дополнительный offline guard проверяет полное покрытие реестра, допустимые статусы, owner, причины исключений, безопасные пути и единственный источник ADR; unit tests проверяют отказы. Проверка примеров выполнена для обновлённых руководств по исходникам Compose/Makefile; все остальные примеры требуют содержательной проверки. Не считать guard доказательством перевода, schema compatibility или E2E.

## Остаётся до DoD

Перевод трёх оставшихся активных security/QA runbooks выполнен; требуется подтверждение классификации остальных материалов и содержательная проверка русскоязычных документов, ревью владельцами, проверка всех legacy-примеров и внешних references, связывание требований/контрактов после принятия #336/#337, фактический CI на точном SHA и независимое review. Production deployment и live provider не подтверждены. Оригиналы прошлых редакций доступны в Git.
