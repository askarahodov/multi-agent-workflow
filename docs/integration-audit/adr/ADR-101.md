# ADR-101: Versioned API Contract

**Status:** Accepted
**Date:** 2026-10-12
**Deciders:** sdlc-architect (TASK-01 EPIC-INT E2)
**Related:** 01-architecture-audit.md, 02-api-incompatibilities.md, 04-dependency-order.md

---

## Context

The frontend (React + TypeScript) and backend subsystems (Orchestration Server, Agent Management, Runtime Hardening) have completely divergent REST API contracts:

- **Frontend HttpAdapter** calls 9 endpoints under `/api/v1/` (workflow definitions CRUD, versions, agent definitions, model profiles, tool policies)
- **Orchestration Server** exposes 17 endpoints at **root path** (no `/api/v1` prefix) — only runtime domain (workflow runs, tasks, attempts, agents)
- **Agent Management** exposes endpoints under `/api/v1/` — only configuration domain (providers, model profiles, tool policies, agent definitions/instances)
- **Runtime Hardening** exposes its own endpoints at root — container/runtime management

**Critical gaps:**
1. **Zero overlap** between frontend-called paths and orchestration-server routes
2. **WorkflowDefinition domain missing entirely** from orchestration-server (frontend expects design-time CRUD, backend only has runtime)
3. **Pagination format mismatch**: frontend uses cursor-based (`after/limit` → `next_cursor`), agent-management uses offset/limit (`offset/limit` → `items/total`), orchestration uses direct arrays
4. **DTO shape mismatch**: frontend expects minimal reference objects, backends return full entities

---

## Decision

1. **Single source of truth:** OpenAPI specification generated by **Orchestration Server** (`services/orchestration-server/docs/openapi.json`) is the authoritative contract.
2. **Versioning via URL prefix:** All public APIs MUST use `/api/v1/` prefix. Breaking changes → `/api/v2/`.
3. **Orchestration Server owns the contract:** It MUST be extended to include the **WorkflowDefinition/WorkflowVersion** domain (design-time CRUD) that frontend requires.
4. **API Gateway / BFF:** Introduce a lightweight gateway (nginx/FastAPI/Traefik) at `/api/v1` that:
   - Routes `/api/v1/workflows/*` → Orchestration Server
   - Routes `/api/v1/agents/*`, `/api/v1/model-profiles`, `/api/v1/tool-policies` → Agent Management
   - Routes `/api/v1/runtime/*` → Runtime Hardening
   - Normalizes pagination to `CursorPage` format across all upstreams
   - Enforces RFC 9457 Problem Details error format
5. **Frontend HttpAdapter** MUST conform to the gateway contract; `mock:false` becomes default after gateway readiness.
6. **MockAdapter** remains ONLY for tests and autonomous offline development.

---

## Consequences

**Positive:**
- Single versioned contract eliminates drift
- Gateway isolates frontend from backend topology changes
- Cursor-based pagination scales better for large datasets
- Clear ownership: Orchestration = runtime + design-time workflow; Agent Mgmt = agent config; Runtime = execution isolation

**Negative:**
- Requires implementing WorkflowDefinition domain in Orchestration Server (new tables, models, endpoints)
- Gateway adds operational component (mitigated: single binary, stateless)
- Migration period where MockAdapter is default for frontend dev

**Migration path:**
1. Add WorkflowDefinition/WorkflowVersion to Orchestration Server (F-01, F-02 in dependency order)
2. Implement CursorPage pagination in Orchestration Server (F-03)
3. Deploy Gateway (F-04) — can start as Vite proxy in dev, nginx in prod
4. Switch frontend `DEFAULT_BASE_URL` to gateway, `mock:false` default
5. Deprecate root-path endpoints in Orchestration Server (30-day sunset)

---

## Rejected Alternatives

| Option | Rejection Reason |
|--------|------------------|
| Frontend adapts to multiple backend bases | Leaks backend topology to UI; unmaintainable |
| Agent Management owns WorkflowDefinition | Wrong domain ownership; Agent Mgmt = agent config, not workflow design |
| gRPC/Protobuf instead of REST | Frontend is browser-based; REST+JSON simpler; gRPC for inter-service later |
| No versioning (evergreen API) | Breaking changes inevitable; versioning protects consumers |
| Merge all services into one monolith | Violates platform principles (provider independence, controlled autonomy); operational coupling |

## Verification

- OpenAPI spec at `/api/v1/openapi.json` validates against `openapi-spec-validator`
- Frontend `HttpAdapter` compiles against generated TypeScript client from spec
- Contract tests: `GET /api/v1/workflows/definitions` returns `CursorPage<WorkflowDefinitionDTO>`
- Gateway routes all `/api/v1/*` correctly (integration test matrix)
