# Трассируемость требований

Версия 0.1, проект для согласования. Задача #338; зависит от #336 (PR #352) и #337. Источник требований: `docs/product/requirements.json`. Матрица: `docs/product/traceability.json`. Машинные файлы хранятся в Git, а не как страницы VitePress.

Первичный реестр содержит 20 требований, все имеют статус planned: независимое соответствие реализации не подтверждено. Issue — связь с планом, а не evidence. Статусы: planned, implemented (PR и SHA), verified (результат теста/CI на том же SHA), accepted (согласованное требование, independent approval, нет блокеров), blocked (причина). 

Проверка `node scripts/check-requirements.js` валидирует уникальность, обязательные поля, покрытие, привязку Issue, полноту и согласованность evidence с указанным candidate SHA. `node --test scripts/check-requirements.test.js` проверяет отрицательные сценарии. CI использует существующий Docs check. Формат evidence не подтверждает подлинность URL, идентичность reviewer или актуальность удалённого SHA: эти факты проверяются независимо через GitHub/QA и operator review, до #349/#333. Не считать структурную проверку принятием. Добавление ADR, contract IDs, release linkage и проверка внешних evidence остаются дальнейшим этапом #338.

Не копировать текст PRD в матрицу; менять требование в каноническом реестре. При изменении candidate пересмотреть все связанные evidence, не переносить автоматически PASS с предыдущего SHA.
