## Matrix C — Resilience Patterns (Resilience4j reference)

| Pattern | Failure it prevents | Starting config | Key pitfall |
|---|---|---|---|
| TimeLimiter | Hung call holding a thread | per-endpoint SLA; `cancelRunningFuture: true` | blanket 30 s timeout |
| Circuit Breaker | Cascade from a failing dependency | window ≥100, min calls ≥20, failure rate 50%, open ≥30 s, half-open ≥3 | tiny window → thrashing |
| Bulkhead | One slow dependency monopolizing resources | semaphore/thread-pool; `maxConcurrentCalls`, small `maxWaitDuration` | skipped assuming vthreads suffice |
| Retry | Transient blips | maxAttempts 3, exp backoff ×2 + jitter, idempotent only, ignore 4xx | retry storms; non-idempotent double-exec |
| Rate Limiter | Overrunning a downstream/quota | limit per period | — |
| Fallback | Hard failure reaching user | stale cache / degraded mode | — |

**Decorator order (outer→inner):** Bulkhead → TimeLimiter → RateLimiter → CircuitBreaker → Retry
(retries inside breaker; open breaker does not retry).

## Matrix D — Isolation Decision Rule

| Workload class | KVM available? | Recommended isolation | Rationale |
|---|---|---|---|
| Trusted internal tooling | either | container + cgroup v2 + restricted SC + inner bwrap/nsjail | cheapest sufficient boundary |
| Untrusted / LLM-authored code | No | **gVisor (runsc)** | userspace syscall boundary without KVM |
| Untrusted / adversarial, multi-tenant | Yes | **Kata-on-Firecracker** | hardware boundary, tiny VMM surface |
| Untrusted / adversarial, multi-tenant | No | gVisor + inner nsjail + strict cgroups + network egress allowlist | best available without KVM; accept residual kernel-bug risk |
