## Blocking findings

### B1 — Performance benchmark is statistically unsound and flaky (HIGH)
`tests/performance/runtime/test_benchmarks.py:104-121`.
The test compares two single raw wall-clock loops of `n = 20_000` `create_args` calls
(hardened vs. flags-emptied) and asserts `overhead < 0.05`. There is no warm-up, no
best-of-N, no median — GC/scheduler noise on a ~10 µs/op workload dwarfs the 5 % budget.
Independently reproduced: **2/15 failures** (0.0521, 0.0657 vs. SLO 0.05); the tester saw
0.2303 on a bad run. The real marginal overhead is ≈1.6 % on clean runs, so this is a
*test-methodology* defect, not an implementation regression — but it means the acceptance
criterion "Performance benchmarks: overhead <5%" and "all test suites pass in CI pipeline"
**cannot be relied on**. (Note `_best_of()` already exists at line 31 and is used by the other
benchmarks — this test just doesn't use it.)

### B2 — Lint/format gate is red (HIGH)
The project README (`README.md` §Development) documents `ruff check .` and
`ruff format --check .` as gates, and the implement card's acceptance criterion is
"Ruff/lint clean". Both fail on the test tree:

### N2 — Graceful shutdown on SIGTERM not implemented (LOW)
The operational checklist requires "Graceful shutdown on SIGTERM (drain in-flight)". No
lifespan/shutdown handler, signal handler, or drain logic exists anywhere in `runtime/`
(grep for `SIGTERM|shutdown|lifespan|on_event|signal.` returns only the seccomp syscall name
`"shutdown"` in `container_runtime.py:193`). `runtime/api.py` relies entirely on uvicorn's
default SIGTERM stop; in-flight agent containers are not drained. Not in the implement card's
acceptance criteria, hence non-blocking for this gate, but it must be closed before production.

## Strengths (verified, not claimed)

- **Real enforcement proven, not just flags.** Integration tests run a live container and prove
  `CapEff=0000000000000000`, a read-only rootfs, seccomp blocking `chmod`, memory OOM kill, and
  workspace scratch isolation.
- **Baseline hardening is unconditional** on every isolation tier (`--read-only`,
  `--cap-drop=ALL`, `--no-new-privileges`, `--init`) and forbids host-exposing flags; a security
  test asserts no `--privileged/--cap-add/--pid=host/...` leak.
- **cgroup v2 invariants enforced**: `memory.swap.max == memory.max`, `memory.oom.group=1`,
  hierarchical/aggregate parent-budget rejection (DoS resistance), and the model layer rejects
  swap/high>max violations.
- **Concurrency safety**: `CircuitBreaker`, `Bulkhead`, `RetryBudget` all guard state with locks;
  resilience semantics (sliding window, half-open, exponential backoff w/ jitter, ~10 % retry
  budget) match ADR-003.
- Type hints complete and `mypy` clean across 10 modules; 92 % branch coverage; specific
  exception types throughout; atomic workspace commit (`os.replace`) and snapshot restore uses
  `tarfile ... filter="data"` (path-traversal safe).

## Known deviations (documented by the implementer — acknowledged, not the blocker)

1. `--userns=keep-id` is Podman-only; Docker relies on a rootless daemon; `UsernsMapping` is
   modelled but not written to `/proc/<pid>/*_map`.
2. overlayfs mount is not performed (host staging + atomic commit instead).
3. `tc` network shaping modelled but not wired to a veth (cgroup v2 cannot enforce it).
4. OpenAPI mTLS/bearer auth declared but not enforced by the reference app.
5. Seccomp uses one generic default-deny allowlist rather than per-agent-type profiles.

## Residual risk

- **No git base** → cannot diff the change set or verify exactly what was added vs. inherited.
- **Integration flake** observed once (docker `inspect` → "no such object" during
  `test_seccomp_profile_blocks_a_syscall`) after a back-to-back full-suite run; 0/8 isolated
  reruns failed. Possible ordering/daemon-contention flake, not reproduced deterministically.
- Default agent id (when `spec.id` omitted) is derived from `hash(spec.name)`

  reproducible across restarts.
