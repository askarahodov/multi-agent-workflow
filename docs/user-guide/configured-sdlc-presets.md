# Конфигурируемые шаблоны SDLC

В **Редакторе** раскрывается **«Собрать готовый процесс из реальных агентов и контрактов»**. Мастер позволяет выбрать:
- «Простой агент» (1 исполнитель + Contract Gate);
- «Разработка + проверка» (2 исполнителя с отдельными настройками + два Gate);
- «Семь стадий SDLC» (7 исполнителей + семь Gate).

Для **каждой** стадии нужно выбрать определение агента, модель и политику инструментов из реальных серверных справочников. Один контракт проверяет выход всех стадий; можно выбрать существующий контракт проекта или явно создать стандартный `summary` (JSON-объект с обязательной непустой строкой summary). Контракт создаётся в backend с project_id. Никаких случайных UUID или пустых ссылок мастеру не разрешено подставлять.

Результат — новый черновик с линейными связями `Start → (Agent → automatic Contract Gate)+ → End`, который проходит локальную проверку и серверный компилятор `published_graph.py`. Создание черновика **не** сохраняет, публикует и не запускает задачу автоматически: пользователь должен нажать **Сохранить**, **Опубликовать**, **Запустить версию**, подтвердив возможные расходы. Перед заменой несохранённого графа требуется отдельное подтверждение.

Важно: роли «Ревьюер», «Тестировщик», «Security» внутри пользовательского workflow сами по себе не дают независимой QA-аттестации. Для полного автономного SDLC по-прежнему обязательны отдельные серверные QA/Contract Gate и human release approval. Поля профилей агентов ещё не полностью enforced нативным worker (см. #254). Шаблон требует, чтобы **каждый** исполнитель возвращал результат, совместимый с выбранной схемой. Не поддерживаемые runtime узлы (condition, parallel, join, tool, memory, delay, human_approval) нельзя считать исполняемыми.

Тесты: frontend Vitest проверяет сохранённые справочники, создание контракта, компиляцию семи стадий, отрицательные ошибки, отмену замены черновика и полный офлайн-сценарий через MockAdapter до `Run`. Реальный Chromium/Compose и live OpenRouter остаются отдельной операторской приёмкой.
