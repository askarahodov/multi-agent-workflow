# Доска задач: серверное состояние исполнения

Доска показывает реальные запуски и задачи orchestration-server, а не Hermes Kanban для разработки платформы (#192). По умолчанию фильтруется выбранный проект. Интерфейс проходит страницы списка запусков и задач по курсору, проверяет принадлежность задач запуску и прекращает обработку при некорректном или повторяющемся курсоре либо превышении ограничения страниц. Источник истины — API; клиентская фильтрация не заменяет серверную авторизацию.

Доска различает ожидание, готовность, исполнение, независимый QA, ручное согласование, блокировку, карантин/восстановление, завершение, ошибку и **неизвестное состояние**. Неизвестное состояние не выдаётся за активное исполнение. Карточка ведёт в фактическое представление задачи, где доступны попытки, QA и Git evidence. Есть поиск, фильтры проекта/запуска/статуса и явное обновление. Перетаскивание не изменяет состояние, клиент не выполняет claim и не помечает работу успешной.

Исторический API запусков может игнорировать projectId, поэтому UI фильтрует по авторитетному run.project_id до чтения задач. Это проверка корректности, а не механизм RBAC. Детальные gate/evidence читаются из API карточки; доска не додумывает результат. Сохранение проекта между перезапусками браузера и полный runtime smoke требуют подтверждения в #255. См. [запуск версии](published-workflow-run.md).
