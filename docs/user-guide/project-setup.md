# Пошаговая настройка проекта (первый UI-проход)

В разделе **Первый запуск** приложение ведёт по четырём шагам: существующий/новый проект → workspace → серверные справочники моделей/агентов/tool-policy → проверка и переход в «Запуски». Все записи сохраняются действующими API; повторный выбор существующего проекта не создаёт дубль. Профили OpenRouter и модели создаются в «Настройках», тест подключения оплачивается только после отдельного подтверждения.

**Границы:** мастер не выдаёт статус готовности native worker, Git, QA или live OpenRouter только по наличию записей. Dev Compose не включает платного диспетчера. Экран «Запуски» пока создаёт собственные tasks отдельно от визуального графа — это основная работа #253. Полноценная конфигурация ролей и budgets остаётся #254. Поэтому данный UI-проход не доказывает полную готовность #252/#254, #11 или #8.

Тест: `cd apps/frontend && npm test -- --run` (см. project npm scripts). Для реальной приёмки дополнительно нужны Playwright/Compose, проектные workspace permissions и protected native worker.
