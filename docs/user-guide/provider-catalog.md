# Каталог провайдеров и совместимые API

В «Настройки → Подключения» выберите OpenRouter, HuggingFace, Custom OpenAI-compatible или offline Mock. Используются существующие адаптеры agent-management. Для Custom задавайте доверенный base URL, обычно с окончанием `/v1`; не передавайте ключ неизвестному серверу. Backend шифрует ключи и не возвращает их интерфейсу.

После создания подключения UI открывает вкладку «Модели» и выбирает сохранённого провайдера. Для активного OpenRouter сервер делает read-only GET к фиксированному каталогу `https://openrouter.ai/api/v1/models`. Ответ содержит ID моделей, контекстные ограничения, поддерживаемые параметры, defaults и строки цен за токен. Каталог можно фильтровать по имени/ID; UI подставляет ID, имя и допустимые defaults temperature/max output tokens. Отдельное сохранение создаёт профиль модели; чтение каталога не расходует inference credits.

Каталог OpenRouter не использует произвольный customer base_url как прокси. У OpenAI-compatible API нет единой гарантированной схемы каталога; ручной ввод model ID сохранён. Доступность для конкретной учётной записи и цены могут меняться. Выбор модели не подтверждает inference, tool-call support или enforcement бюджета. См. #254/#11.

Замена ключа предусмотрена для подключений с credentials; сохранённый ключ не отображается. Реальная проверка соединения отличается от чтения каталога и требует согласования возможных расходов. См. [настройку](configuration.md).
